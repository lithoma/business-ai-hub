### Genie One MCP transport — 2026-10-21

The new `genie_one_mcp.py` is a small transport adapter, separate from the existing A1/A2 APIs. It restricts the destination to the authenticated Workspace's current `system.ai.genie_one_mcp` Unity Gateway URL, reuses `WorkspaceClient.config.authenticate()`, and uses the MCP Python 1.x Streamable HTTP client. It does not add a model/tool-selection loop or pull the MLflow/AI Bridge stack into this App. Synchronous operations belong in sync routes/workers. Tool discovery is paginated and does not invoke Genie analytics.

The adapter requires explicit trusted caller context, retains tool schemas per adapter instance and rejects another caller before network activity. It exposes only `genie_ask`, `genie_poll_response`, `genie_get_query_result` and `genie_cancel_response`, validates inputs against discovered JSON Schemas, preserves structured/text envelopes separately, validates advertised structured output, bounds result size and rejects tool errors. It does not guess argument names, infer a completed answer from arbitrary text, retry failed calls, switch identities, or silently fall back to legacy services. The MCP transport's own HTTP behavior is not an application inference retry loop.

`scripts/check-genie-one.py --profile business-ai-hub` performs only authenticated initialization and tools/list. It prints schemas on success, or sanitized exception types/provider codes on failure; no token or raw authentication exception is printed. Run with the project's Python environment. ## Guard and execution contract

- One SELECT/WITH query (including SELECT UNION); DDL/DML, commands, SELECT INTO, unrecognized/custom functions and external table functions are rejected before a Warehouse client is obtained. Standard built-ins and unqualified Metric View `MEASURE` are supported. AI/remote/write function families are disallowed.
- Warehouse testing uses one Statement Execution request, two-row result limit, 16 KB result cap, 50-second wait with cancellation on wait timeout. Truncated, multirow, null, numeric or string-typed trigger decisions fail explicitly. No repair loop is added.
- This is structural SQL validation plus Databricks execution permissions, not proof of metric correctness or an isolation boundary for arbitrary view internals. Use appropriate read-only data privileges for integration. No privileges were changed here.
- Supported date parameters: `business_date`, `period_start`, `period_end`, `previous_period_start`, `previous_period_end`. Complete week, single day and rolling seven-day windows are available. The preserved simulation offset (487 days) determines the default test business date; the user can override it for a test.
- Exact sample date literals in Genie SQL are replaced as SQL AST nodes with date parameters, prioritizing period boundaries. The user must review this transformation. Other fixed dates and SQL-native clock expressions are not guaranteed to follow the platform date context; inspect the query rather than assuming every displayed parameter is used.
- For saved Registry SQL tasks, the existing executor recomputes the selected comparison window on each actual dispatch. Existing YAML date behavior is retained. SQL testing itself never calls the report Agent or publishes notifications.
- Test receipts cover SQL hash, window and expiration; they attest a successful sample query, not future data availability or business accuracy. Multiple production workers need the same secret-backed `TASK_SQL_REVIEW_SECRET`. The local server keeps its generated signing key beside its local database with mode 0600, outside Git.
