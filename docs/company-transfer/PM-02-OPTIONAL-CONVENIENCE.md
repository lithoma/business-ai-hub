# 申请二：Business AI Hub 可选便利条件

日期：2026-10-21。本清单用于“如果可批准，会更方便”的事项，不是本机试点的前置条件。第一份必要条件具备后，可先做交互验收；以下按需要逐项申请，不必全部批准。

| 优先级 | 可选事项 | 具体申请范围 | 收益/依赖 |
|---|---|---|---|
| 1 | 公司邮件发送 | 指定一个公司认可的发件身份及一种已有邮件 API/SMTP 通道，限定试点收件范围；按 IT 政策给最小发送权限和必要网络访问 | 验证真实报告邮件。当前有 Gmail 适配器；公司选用其他通道时需补发送适配，不默认使用个人 Gmail |
| 2 | 内网同事访问 | IT 批准其他试点电脑访问运行电脑的一个指定内网端口；最好有固定内网地址，并限定访问范围 | 同事通过浏览器试用，不必各自安装。不需要公网域名或对公司使用公开隧道；共用一个身份时，他们共享其数据范围 |
| 3 | 本机持续运行/定时执行 | 允许批准的程序随登录/启动运行或由本机调度器触发；确认可持续运行的电脑与存放目录，以及获准的无人值守登录方式 | 不用因此申请 Databricks Job。调度入口仍需代码适配；CLI/SDK 凭据会受公司刷新/失效策略约束，不能承诺永久免登录 |
| 4 | 云端保存任务与历史（仅需要时） | 在已有合适的受控 Schema，或经 Terraform 批准的专用 Schema，建立两张表：business_task_registry_v1、business_task_runs_v1。授予选定运行身份父级 USE 及仅两表 SELECT/MODIFY；检查继承权限，不让非试点人员直接读取报告 | 便于换电脑和集中保存。若本机 SQLite 已足够，此项完全可以不申请；新云表存储适配需单独接入，不会因授权自动切换 |
| 5 | 专用运行身份（需要长期后台时再选） | 先确认公司是否已有可复用的批准运行账号/服务身份。若选择替代个人试点账号，只授权既定 Genie/数据、Warehouse、模型及所选任务存储的必要范围，不授管理或业务数据写入权限；凭据由 IT 管理 | 减少依赖某人的个人登录。属于另一种明确的共享运行模式，需要代码适配及迁移任务归属；不能静默替代原任务创建者身份，也不是第一阶段的硬性要求 |

推荐顺序：先批准“邮件”和“内网访问”（若需要），再视实际演示情况选择“持续运行”。云端任务表与专用身份可延后。

此阶段不申请全库读写、ALL PRIVILEGES、Agent 编辑/管理、Warehouse 管理、新建模型或全局管理员权限。多人各自权限隔离及自定义 Web OAuth 属于后续独立方案，不混入本次便利清单。

以上审批只提供运行条件或资源访问；本机调度、公司邮件适配、云存储切换等尚需对应代码接入及验收。公司资源、授权和调度不会由本清单自动变更。

凭据仅配置到公司批准的运行环境，不返回聊天/文档或进入 ZIP/Git。
